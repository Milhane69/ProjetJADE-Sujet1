1 . Les données proviennent de fichiers JSON et Excel :
abstrats-2023-01-12.json
rubriques-2023-01-12.json
extraction table decisionset.xlsx
type sous type.xlsx

Ces fichiers sont importés dans des tables brutes appelées tables de staging, puis transformés par jointure afin de produire une table finale enrichie : bstracts
Cette table finale contient les données utiles pour l’analyse juridique, le NLP et les futurs traitements IA.

2. Environnement utilisé:
Windows
Visual Studio Code
PostgreSQL 17
pgAdmin 4
Python 3.12

Bibliothèques Python:
json
pandas
psycopg2
Role:
json       → lire les fichiers JSON
pandas     → lire les fichiers Excel
psycopg2   → se connecter à PostgreSQL et exécuter des requêtes SQL

4. Rôle des dossiers:
4.1 data/raw:
Ce dossier contient les fichiers sources bruts.
Ces fichiers ne sont pas modifiés directement. Ils servent uniquement à alimenter la base PostgreSQL.

4.2 sql:
Ce dossier contient les scripts SQL.
4.2.1 01_init_database.sql
Ce fichier crée les tables nécessaires au pipeline :
abstracts_raw
rubriques_raw
decisions_raw
types_raw
abstracts

4.2.2 02_Init_rejet.sql
Ce fichier crée une table de rejet :
abstracts_rejets
Elle sert à stocker les lignes problématiques, par exemple lorsqu’un abstract ne trouve pas de décision correspondante.

4.2.3 03_init_test_qualité.sql
Ce fichier contient des requêtes de test permettant de vérifier la qualité des données après transformation.

5. Rôle des tables PostgreSQL
5.1 Tables de staging
abstracts_raw
Rôle :
Cette table contient les abstracts juridiques.
Champs principaux : Le champ le plus important est : resume_abstrat
id
statut_abstrat_id
resume_abstrat_id
rubrique_id
decision_id
solution_implicite
resume_abstrat
renvoi_rubrique_id
motifs

5.2 rubriques_raw
Rôle :
Cette table contient la hiérarchie des rubriques juridiques.
Elle permet de transformer : rubrique_id en thème juridique lisible.

5.3 decisions_raw
Rôle :
Cette table contient les métadonnées des décisions.
Elle permet de relier : abstracts_raw.decision_id avec decisions_raw.id
Elle apporte :
date_decision
intitule
reference_officielle
ecli
type_decision_id
sous_type_decision_id

5.4 types_raw
Rôle :
Cette table permet de donner un sens aux types et sous-types de décisions.
Elle permet de transformer :
sous_type_decision_id
en libellé compréhensible.
Exemple :
QPC-renvoi → Question prioritaire de constitutionnalité renvoi

5.5 abstracts
C’est la table finale enrichie.
Elle est obtenue après jointure entre :
abstracts_raw
rubriques_raw
decisions_raw
types_raw
Elle contient uniquement les champs utiles pour l’analyse :
id_abstract
reference_officielle
date_decision
theme_juridique
texte_brut
motifs_invoques
type_recours
date_import

6. Scripts Python
6.1 import_database.py
Ce script initialise la base de données.
Il permet de : supprimer les anciennes table , recréer les tables , créer les index
Commande :
python src/etl/import_database.py

6.2 import_abstracts.py
Ce script lit : abstrats-2023-01-12.json et insère les données dans : abstracts_raw
methode complexe :
json.load(f) = sert à transformer le fichier JSON en objet Python.

for key, value in data.items() = sert à parcourir chaque abstract du fichier JSON.

json.dumps(value.get("motifs", [])) = sert à convertir la liste Python des motifs en JSON compatible avec PostgreSQL JSONB.

6.3 import_rubriques.py
Il fonctionne de la même manière que import_abstracts.py, car le fichier source est aussi en JSON.

6.4 import_decisions.py
Ce script lit : extraction table decisionset.xlsx
methode complexe :
df.iterrows() = sert à parcourir les lignes du fichier Excel.

None if pd.isna(...) else ... = sert à transformer les cellules vides Excel en NULL PostgreSQL.

6.5 import_types.py
Ce script lit : type sous type.xlsx
Il importe les informations utiles :
id du sous-type
code du type
libellé du sous-type

6.6 run_pipeline.py
Ce script sert à automatiser tout le pipeline.
Il peut exécuter :
scripts SQL
scripts Python d’import
restauration éventuelle d’un dump PostgreSQL
Il permet de lancer tout le pipeline avec une seule commande.

6.7 data_quality.py

Ce script réalise :
- les jointures entre les tables staging
- le nettoyage des données
- la validation qualité
- la gestion des rejets
- l’insertion dans la table finale abstracts

Règles de qualité appliquées :
- référence officielle obligatoire
- date de décision obligatoire
- texte de l’abstract supérieur à 10 caractères

Les lignes invalides sont stockées dans :
abstracts_rejets

Les erreurs sont également enregistrées dans :
logs/qualite_donnees.log
